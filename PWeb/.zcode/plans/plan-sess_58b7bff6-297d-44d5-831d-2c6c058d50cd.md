# PWeb: 正则捕获组重写 + HTTPS 代理 + Windows 多监听 select 修复

## 关键发现（决定方案）
- **MinGW 工具链没有 `regex.h`** → 写一个 ~150 行的内置 POSIX 风格正则引擎（匹配 + 捕获组 + `$n` 替换），双平台、零依赖，符合 PWeb 定位。
- **POSIX 版 `handle_proxy`（handlers.c:359）被截断**，响应转发循环缺失（到 458 行中间结束）→ 本任务顺带修复（以 `_win_stubs.c` 完整版为模型）。
- **Windows select 挂起根因**：`while(1)` accept-drain 阻塞整个循环 + 线程创建失败时内联处理连接。改为**每个监听 socket 一个阻塞 accept 线程**（只有 np 个线程，符合 0.5C/512M）。
- OpenSSL 仅在 `C:\\msys64\\ucrt64`（头 + `libssl.dll.a`/`libcrypto.dll.a`），与 MinGW ABI 不匹配 → SSL 做成**编译开关（`PWEB_SSL`）**，默认构建保持零依赖，不破坏现有 `pweb.exe`。

## 功能 1：正则捕获组重写（`$1`/`$2`）

**新文件 `util.c` + `pweb.h`：内置正则引擎**
- 支持字符集：`.` `*` `?` `+` `[]` `( )` 捕获组、转义 `\\`、字面量；**不支持** 前瞻/环视/递归（够用即可）。
- 经典 backtracking `regexec` 语义，最多 9 个捕获组（Nginx 上限）。
- API（加到 `pweb.h`）：
  ```c
  int  pweb_re_compile(const char *pat, char *out, size_t n);  /* 校验 + 转存 */
  int  pweb_re_match(const char *pat, const char *s, char caps[9][512], int *n);
  int  pweb_re_sub(const char *pat, const char *s, const char *repl, char *out, size_t n); /* 展开 $1..$9 */
  ```
- `pweb_re_sub` 扫描 `repl` 中的 `$` + 数字，替换为捕获组；处理 `$$` → 字面 `$`。

**`pweb.h` — `loc_t` 增加字段**
- 保留 `redir[512]`，但拆为两个定长字段更安全：`redir_pat[256]`、`redir_repl[256]`。改 `config.c` 的 `rewrite` 解析（config.c:284-288），把 `dv` 存 `redir_pat`、`dd->vals[1]` 存 `redir_repl`，**第 3 个 token 存 `lc->redir_flag`**（`last|break|permanent`，区分 301/302）。

**`conn.c` `locate()`（14-50）**
- 移除 `if (lc->is_regex) continue;`。
- 正则 location 用 `pweb_re_match(lc->match, target, caps, &n)` 判断命中；命中即返回（正则优先级高于前缀，与 Nginx 一致：先扫正则，再回退前缀最长匹配）。

**`handlers.c` `handle_redir()`（560-581）**
- 签名加 `const char *uri`：`handle_redir(fd, lc, req, uri)`（`uri` = conn.c 里已解码的 `target`；更新 `pweb.h:195` 原型 + `conn.c:217` + `_port_conn.c:213` 调用点）。
- 内部：`pweb_re_sub(lc->redir_pat, uri, lc->redir_repl, out, sizeof out)` 生成 `Location`。
- 状态码：`lc->redir_flag` 为 `last`/`break` 时保持 302（或内部跳转），`permanent` → 301。最小实现：默认 301，`last`/`break` 时 302。
- **正则 location 未命中 / 无 rewrite 时**回退 404。

**`_port_*` 同步**：以上改动在 `conn.c`/`handlers.c`/`config.c`/`util.c`/`pweb.h` 上做完后，重新导出对应 `_port_*.c`（保持既有的 `close→PWEB_CLOSE`、`recv→PWEB_RECV` 等桥接规则）。

## 功能 2：`proxy_pass https://`（TLS 客户端）

**`pweb.h` 增加 `PWEB_SSL_*` 桥接宏（`#ifdef PWEB_SSL` 门控）**
- 有 `PWEB_SSL` 时：`#include <openssl/ssl.h>`，映射 `PWEB_SSL_CTX_NEW/SSL_NEW/SSL_SET_FD/SSL_CONNECT/SSL_READ/SSL_WRITE/SSL_FREE/SSL_SHUTDOWN`。
- 无 `PWEB_SSL` 时：全部映射为「返回 501」的桩（保证默认构建零依赖、可编译）。

**`handlers.c` `handle_proxy()`（359，**同时修复截断**）**
- 完整重写：以 `_win_stubs.c:21-132` 的结构为准，补齐 POSIX 缺失的响应流转发循环（`recv`/`send` 泵，8KB chunk）。
- `https://` 分支不再 501：若 `PWEB_SSL` 启用，`SSL_CTX_new(TLS_client_method())` + `SSL_new` + `SSL_set_fd(up)` + `SSL_connect`；请求体走 `SSL_write`，响应流走 `SSL_read`；`X-Forwarded-Proto` 改 `https`（handlers.c:440）。
- 未启用 `PWEB_SSL` 时，`https://` 仍返回 501（带提示），行为与现状一致。

**`_win_stubs.c` `handle_proxy()`（29-32）**：同样的 `PWEB_SSL` 门控分支（Windows 下若 OpenSSL 头可用则走 SSL，否则 501）。

**构建**：`Makefile` / `Makefile.win` 增加可选开关 `SSL=1`（`-DPWEB_SSL -I C:/msys64/ucrt64/include -LC:/msys64/ucrt64/lib -lssl -lcrypto`）。默认关闭。

## 功能 3：Windows 多监听 select 挂起（最高优先级）

**`_port_main.c`（102-167）改为「每个监听 socket 一个阻塞 accept 线程」**
- 新增 `static void *listener_thread(void *arg)`：对单个 `fds[i]` 做 `accept()` 循环（**阻塞 accept，不再 select**），每接受一个连接就 `_beginthreadex` 起连接线程；监听线程随 `g_sigterm` 退出（用 shutdown/关闭 listener 使其 unblock）。
- `main` 里：对每个 listener 起一个 listener 线程，主线程 `wait` 这些句柄（`WaitForMultipleObjects` / 轮询 `g_sigterm`）。
- 好处：消除 `while(1)` drain 对其它 listener 的饥饿，修复 8099 直连挂起；线程数 = np（小），内存可忽略。
- 顺带消除「线程创建失败→内联处理」的阻塞隐患（listener 线程里失败就直接 `accept` 后内联，不再卡主循环）。

**`main.c`（POSIX，135-168）保持 select 模型不变**（POSIX select 无此 bug），只把新增的 listener 线程逻辑放进 `#ifndef PWEB_PLATFORM_WIN` / `#else` 分支，避免影响 POSIX 构建。

## 风险
- 内置正则引擎是手工代码，需单测覆盖（含嵌套/量词/分组边界）——加一个 `test_regex.c` 小自测。
- OpenSSL ABI（UCRT vs MinGW）不匹配可能导致链接失败；用编译门控隔离，不影响默认构建。
- 线程数增长（每个 listener 一个 + 每连接一个）在 0.5C 上可接受，因为 listener 线程阻塞在 `accept`，几乎不耗 CPU。
